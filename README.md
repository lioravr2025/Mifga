# Mifga (מפגע)

אפליקציית דיווח מפגעי דרכים בסגנון Waze, מבוססת קהילה, בנויה קודם כל למובייל עם עיצוב כהה שמכוון לבני נוער (16+).

האפליקציה רצה בשני מצבים, לפי מה שמוגדר בקובץ `.env` (ראו "חיבור לשרת אמיתי" למטה):
- **מצב מקומי (ברירת מחדל):** הכל בצד הלקוח, בלי שרת, בלי שום מידע יוצא מהמכשיר (הכל ב-`localStorage`) - זה
  המצב שרץ אוטומטית ב-`npm run dev` בלי שום הגדרה.
- **מצב מחובר לשרת:** מפגעים, הזדהות, ונקודות מנוהלים דרך Supabase אמיתי (self-hosted), משותפים בזמן אמת בין
  כל המשתמשים - זה המצב המיועד ל-APK שמופץ לקבוצת בודקים.

## הטכנולוגיה

- React + TypeScript + Vite
- Tailwind CSS (עיצוב כהה/בהיר, ממשק RTL בעברית)
- react-leaflet + מפות OpenStreetMap/CARTO (לא נדרש מפתח API מקומית)
- Nominatim (השלמה אוטומטית של כתובות) + מנתב OSRM לדוגמה (תכנון מסלול) - שני שירותי OSM חינמיים שלא דורשים מפתח,
  בשימוש רק בטאב תכנון המסלול
- שלד Capacitor כבר מוכן (`capacitor.config.ts`) לקראת בניית Android/iOS ילידית

> הערת ייצור: כשתרצו לעלות לאוויר, יש להחליף את שכבת המפה של CARTO ואת הקריאות ל-Nominatim/OSRM ב-Google Maps
> SDK / Directions API (בהתאם לדרישה המקורית "מבוסס Google Maps") - שכבת הסמנים/הדיווחים לא תלויה בספק המפה
> ולא צריכה להשתנות.

## הרצה מקומית

```bash
npm install
npm run dev
```

נפתח בכתובת `http://localhost:5173`. מכיוון ש-`server.host` מופעל ב-`vite.config.ts`, אפשר גם לפתוח את כתובת
ה-"Network" שמודפסת בטרמינל ישירות מהטלפון (באותה רשת wifi) כדי לבדוק בגודל מובייל אמיתי לפני בניית ה-APK.

## מה חדש בגרסה הזו

- אפשר עכשיו להריץ את האפליקציה מול שרת Supabase עצמאי במקום `localStorage` - הזדהות, מפגעים, ונקודות
  משותפים בזמן אמת בין כל המשתמשים. פרטים מלאים בסעיף "חיבור לשרת אמיתי" למטה, ומדריך פריסה מלא ב-`DEPLOYMENT.md`.

**מצב נסיעה** 🛴
- כפתור "תחילת נסיעה" ירוק בעמוד הראשי ובטאב מסלול - עגול, גדול, וצף מעל קו התפריט התחתון

- יומן נסיעות בפרופיל: 3 הנסיעות האחרונות מוצגות ישירות, וכפתור "נסיעות קודמות" פותח היסטוריה מלאה עם גלילה;

- מסך קבלת פנים בכניסה הראשונה לאפליקציה: מסביר את הרעיון (נסיעה בטוחה יותר, פחות דוחות), ומציג נתונים חיים -

  לי כלי"), ובחירת סוגי ההתראות הרצויים

**שם משתמש וחיפוש חברים**
- לכל משתמש שם משתמש ייחודי, עם בדיקת זמינות חיה בזמן ההקלדה (גם בהרשמה וגם בעריכת פרופיל מאוחר יותר)
- חיפוש חבר לפי שם משתמש בעמוד החברים, ותצוגת ה-@username ליד כל חבר ברשימה

**הזמנת חברים**
- כפתור שיתוף שפותח את תפריט השיתוף הטבעי של המכשיר (וואטסאפ, טלגרם, SMS, ומה שמותקן) עם הודעה מוכנה מראש

**פידבק במקום פרסומת**
- מקום הבאנר הפרסומי הישן תופס עכשיו כפתור "תנו פידבק על האפליקציה" - לייק/דיסלייק ואז שדה טקסט חופשי (מה
  אהבתם / מה לשפר)

**תיקוני עיצוב ובאגים**
- תוקנה אנימציית ההבהוב בכפתורי תחילת/הפסקת נסיעה - במקום שהכפתור כולו יהבהב, יש עכשיו טבעת דופקת נפרדת מאחוריו
  והכפתור עצמו יציב
- הכפתור העגול "תחילת נסיעה" בעמוד הראשי תוקן כך שהוא מוצג שלם מעל שכבת המפה (לא חתוך/מוסתר חלקית מאחוריה)
- תוקן חישוב משך הנסיעה ביומן (בעבר הציג תמיד "דקה אחת" גם בנסיעות ארוכות יותר)
- טאב "מפה" שונה לשם "ראשי" והועבר להיות הימני ביותר; סדר הטאבים עכשיו: ראשי, מסלול, חברים, פרופיל
- העשרה משמעותית של רשימת דגמי הכלים בפרופיל, כולל מותגים ישראליים נפוצים (INOKIM, Carbon, Rider)

## חיבור לשרת אמיתי (Supabase)

כדי להריץ את האפליקציה מול שרת אמיתי במקום `localStorage`:

1. להקים שרת Supabase עצמאי - יש הוראות מלאות, שלב-אחר-שלב, ב-**`DEPLOYMENT.md`** (מותאם לפריסה על Coolify).
2. להריץ את **`supabase/schema.sql`** מול בסיס הנתונים (ב-Studio → SQL Editor) - יוצר את כל הטבלאות, ההרשאות
   (RLS), והפונקציות.
3. להעתיק את `.env.example` ל-`.env.local` ולמלא את `VITE_SUPABASE_URL` ו-`VITE_SUPABASE_ANON_KEY` שהתקבלו
   מהפריסה.
4. `npm run build` (או `npm run dev`) - האפליקציה מזהה אוטומטית שיש הגדרה ועוברת למצב מחובר.

**מה כבר מחובר בפועל למצב הזה:**
- **הזדהות משתמשים** - הרשמה אנונימית אמיתית (Supabase Anonymous Auth): כל משתמש מקבל חשבון וסשן אמיתיים בלי
  צורך בסיסמה/SMS - מתאים בול לקבוצת בודקים סגורה שמקבלת APK בלי חנות. **מגבלה לדעת:** אם מוחקים את נתוני
  האפליקציה או מתקינים מחדש, מאבדים את הזהות (אין שחזור סיסמה) - שדרוג טבעי להמשך הוא הזדהות עם קוד ב-SMS,
  שדורש ספק SMS מוגדר ב-Supabase.
- **מפגעים** - דיווח, הצבעת "עדיין שם/כבר לא שם", והסרה אוטומטית אחרי 5 דיווחי הסרה - הכל דרך פונקציות
  אטומיות במסד הנתונים (מונעות מירוץ תוצאים/הצבעה כפולה), עם **סנכרון בזמן אמת**: כל דיווח או הצבעה של כל
  משתמש מופיעים מיד אצל כולם.
- **פרופיל ונקודות** - שם, שם משתמש (עם בדיקת ייחודיות מול השרת בזמן ההקלדה), טלפון, כלי, ונקודות/דיווחים
  נשמרים ומתעדכנים בשרת.

**מה עדיין מקומי בכל מצב (גם כשמחוברים לשרת) - כיוון מוכן להמשך:**
- חברים, קבוצות ווקי-טוקי, יומן נסיעות, ומשוב - עדיין רק ב-`localStorage` על המכשיר. הטבלאות המתאימות
  (`friendships`, `walkie_groups`, `ride_log`, `feedback` וכו') כבר מוגדרות ב-`supabase/schema.sql` ומסומנות
  שם כ-RESERVED - החיבור בקוד לא נעשה עדיין, בכוונה, כדי לשלוח פיצ'ר אחד עובד ובדוק (הזדהות + מפגעים) לפני
  שממשיכים לשאר.
- תמונות (דיווחים ואווטאר) עדיין נשמרות כ-base64 בטור הטקסט עצמו, לא ב-Supabase Storage (ה-bucket כבר קיים
  בסכמה, מוכן לחיבור עתידי) - עובד לקבוצת בדיקה קטנה, לא מומלץ לקנה מידה גדול יותר.

## מה כבר מוכן

**מפה, נסיעה ודיווח**
- מסך בית עם מפה, זום צמוד למיקום החי של המשתמש, וסמנים לכל סוג מפגע
- מצב נסיעה עם התרעות קוליות והילת הגנה חיה (ראו "מה חדש בגרסה הזו" למעלה)
- שני סוגי מפגעים ראשיים מוצגים ישירות (שוטר/פקח, גדולים יותר, עם סמן פועם בעדיפות גבוהה); כל השאר נמצאים תחת
  מגירת "עוד": חור בכביש, רכב מפריע, מדרכה משובשת, מצלמה, תאונה, עבודות בכביש, כביש חסום, הצפה, בעל חיים
- תהליך דיווח בקליק אחד: בחירת סוג → מיקום (GPS נוכחי, הקלדת כתובת עם השלמה אוטומטית, או גרירת סיכה על המפה) →
  כינוי אופציונלי לדיווחי שוטר/פקח → תמונה אופציונלית → נקודות (1, או 5 עם תמונה) → קונפטי בסיום השליחה
- הצבעת קהילה "עדיין שם?" על כל מפגע: מספר לייקים חי + זמן הלייק האחרון, קונפטי על כל הצבעה; 5 דיווחי "כבר לא שם"
  מסירים מפגע אוטומטית
- הסמן העצמי מציג את אייקון הכלי שהמשתמש בחר (קורקינט / אופניים חשמליים / אופנוע חשמלי); לחיצה עליו פותחת כרטיס
  פרופיל לצפייה בלבד (אווטאר, רמה, נקודות, כלי ודגם) - מה שחבר היה רואה בלחיצה עליכם

**חברים וקבוצות**
- טאב חברים: חיפוש לפי שם משתמש, נוכחות על המפה, מרחק, נקודות, קיצור "איתור על המפה", הודעת ווקי-טוקי קולית
  (החזקה ושחרור; משתמש במיקרופון האמיתי כשזמין, ומדמה את הזרימה כשלא - כדי שהפעולה תמיד תעבוד)
- אפשר לסמן עד 3 חברים כמועדפים - הם מופיעים במסך הבית עם כפתור מיקרופון מהיר
- קבוצות ווקי-טוקי: יצירת קבוצה ומתן שם, הזמנת חברים (ממתינים עד ש"יאשרו" - מדומה), ניהול חברי הקבוצה
  (הוספה/הסרה, צפייה בזמן חיבור אחרון), שליחת הודעה קולית לקבוצה וצפייה באישורי מסירה לכל חבר
- הזמנת חברים חדשים לאפליקציה דרך שיתוף (ראו "מה חדש בגרסה הזו")

**פרופיל וגיימיפיקציה**
- עריכת שם, שם משתמש, טלפון, תמונה, וכלי (סוג + דגם, עם השלמה אוטומטית מרשימת דגמים עשירה וגם טקסט חופשי לכל
  דגם שלא ברשימה)
- נקודות, רמה/תואר עם פס התקדמות, סטטיסטיקת דיווחים, יומן נסיעות, טבלת "המדווחים המובילים" מול החברים

**תכנון מסלול**
- "תכנון מסלול בטוח ממפגעים": חיפוש כתובת → מסלול עם זמן/מרחק, ודגל לכל מפגע מדווח שנמצא בטווח של כ-120 מטר
  מהמסלול, עם אפשרות להתחיל נסיעה גם בלי מסלול מתוכנן

**הגדרות**
- מצב כהה/בהיר, הרשאת התראות + בחירת סוגי מפגע להתראה (שוטר/פקח/אחר) + רדיוס התראה
- רדיוס ההתרעה הקולית בזמן נסיעה (100-1000 מטר)
- מגבלת התראות יומית: מסלול חינמי (עד 3 ביום) מול מסלול "ללא הגבלה" נעול, שנפתח דרך הזמנת חבר (מזינים את הטלפון
  שלו, נוצרת הודעת הזמנה שמציינת מי הזמין ומאיזה כלי הוא רוכב) במקום תשלום אמיתי - אין חיבור לסליקה בפועל, זו
  רק הדגמה של מנגנון הצמיחה המיועד
- כפתור פידבק על האפליקציה (ראו "מה חדש בגרסה הזו")

## מצב ושמירה

**במצב מקומי:** כל המצב חי בקובץ `src/context/AppContext.tsx` ונשמר ל-`localStorage` (ראו `src/lib/storage.ts`),
עם מפתח נפרד לכל תחום (`mifga:user`, `mifga:friends`, `mifga:hazards`, `mifga:groups`, `mifga:settings`,
`mifga:rideLog` ועוד). הטעינה משלימה שדות חסרים עבור מידע שנשמר בגרסה ישנה יותר של הסכמה, כך ששדרוג האפליקציה
במקום לא שובר מידע קיים על המכשיר.

**במצב מחובר לשרת:** משתמש, מפגעים, ונקודות חיים בטבלאות Supabase (`profiles`, `hazards`) במקום ב-`localStorage`
- ראו "חיבור לשרת אמיתי" למעלה. חברים/קבוצות/יומן נסיעות/משוב עדיין ב-`localStorage` גם במצב הזה, בכוונה (ראו שם).

## בניית ה-APK

1. `npm run build`
2. `npx cap add android` (דורש Android Studio/SDK מקומית, או הרצה דרך CI)
3. `npx cap sync android`
4. בניית ה-APK מתוך Android Studio או `./gradlew assembleDebug`

`npx cap add ios` עובד באותו אופן ברגע שיש סביבת macOS/Xcode זמינה - שכבת הווב לא דורשת שום שינוי כדי לתמוך בזה.
